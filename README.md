# Gaussian Blur: C++ и Python

Лабораторная работа «Многоязыковое программирование». Реализованы семь
вариантов из предоставленного отчёта: C++-библиотеки, Python-программа
с `ctypes`, чтение и сохранение изображений, сравнение производительности.

## Техническое задание

Инструментальная и целевая платформы: GNU/Linux, GCC, Python 3.
Вход: изображение, преобразуемое в RGB. Выход: размытое изображение.
Ввод-вывод и интерфейс командной строки реализованы на Python,
вычисления выполняются в динамической библиотеке C++.

Размер ядра и обработка границ в отчёте не определены. Здесь используется
гауссово ядро 3×3:

```text
1 2 1
2 4 2  / 16
1 2 1
```

Свёртка разделена на горизонтальный и вертикальный проходы с весами
`[1, 2, 1] / 4`. Крайние пиксели продолжаются за границы изображения.
Каналы RGB обрабатываются независимо, промежуточные данные имеют тип
`float32`. Каждая следующая итерация размывает результат предыдущей.
Округление до целых и ограничение диапазоном 0–255 выполняются при сохранении.

## Сборка в Linux

Fedora:

```bash
sudo dnf install gcc-c++ make python3 python3-pip
```

Debian/Ubuntu:

```bash
sudo apt install g++ make python3 python3-pip python3-venv
```

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
make -j4
make test
```

Библиотеки появляются в `build/`. `libgaussian_blur.so` содержит финальную
многопоточную реализацию. `-march=native` означает сборку под текущий процессор;
на другом компьютере следует собрать библиотеки заново.

## Запуск

```bash
python3 main.py blur input.jpg results/blurred.png --threads 4
python3 main.py blur input.jpg results/scalar.png --variant scalar_o0 --iterations 1
python3 main.py benchmark --threads 4
```

Benchmark по умолчанию обрабатывает RGB-изображение 1920×1080 в течение
1000 итераций, как в отчёте. Входные данные генерируются с seed=42.
Можно передать собственное изображение через `--input image.png`.
Для короткой проверки:

```bash
python3 main.py benchmark --width 320 --height 180 --iterations 10
```

`--repeats 3` запускает три замера каждой версии и использует медиану.
Перед замерами выполняется одна прогревочная итерация.
Каждый замер начинает с одного и того же исходного изображения. Результаты
всех версий сравниваются с `scalar_o0`, абсолютная погрешность не более 0.0001.

## Варианты

| Имя | Реализация | Флаги |
| --- | --- | --- |
| scalar_o0 | Один поток, без SIMD | `-O0 -fno-tree-vectorize -fno-tree-slp-vectorize` |
| scalar_o3 | Один поток, без SIMD | `-O3 -march=native -fno-tree-vectorize -fno-tree-slp-vectorize` |
| simd_o0 | SIMD без выравнивания | `-O0` |
| simd_o3 | SIMD без выравнивания | `-O3 -march=native -ftree-vectorize` |
| aligned_o0 | SIMD с выравниванием | `-O0` |
| aligned_o3 | SIMD с выравниванием | `-O3 -march=native -ftree-vectorize` |
| parallel | SIMD с выравниванием, OpenMP | `-O3 -march=native -ftree-vectorize -fopenmp` |

SIMD задан явно в исходном коде через расширение GCC `vector_size(16)`:
одновременно обрабатываются четыре `float`. Поэтому векторизация присутствует
и при `-O0`. Для скалярных вариантов автоматическая векторизация отключена.
Во всех версиях отключено слияние умножения и сложения (`-ffp-contract=off`).

Буферы выделяются через `posix_memalign` с выравниванием 64 байта, длина
строки округляется до 16 элементов. В вариантах без выравнивания рабочие
указатели намеренно сдвинуты на один `float`; SIMD-чтение и запись выполняются
через `memcpy`. В выровненных версиях используются выровненные векторные
чтения центральных элементов и записи. Горизонтальные соседи сдвинуты на
три элемента из-за RGB и всё равно требуют невыровненного чтения.
Края строки и остаток после векторного цикла обрабатываются скалярно.

OpenMP распределяет строки между потоками; после каждого прохода действует
неявный барьер. Потоки пишут в отдельные строки выходного буфера.

## Измерения

`results/benchmark.csv` содержит время, производительность, сложность,
эффективность, ускорение относительно базовой версии и количество потоков.
Рядом сохраняется JSON с платформой и параметрами запуска.

Измеряется полный вызов C++ через `ctypes`, включая выделение внутренних
буферов и копирование данных. Чтение изображения, выделение массивов Python,
проверка результата и запись изображения в это время не входят.

Формулы из задания:

```text
Perf = 1 / T
Comp = число непустых строк src/gaussian_blur.cpp
P = floor(Perf / Comp * 1000000)
```

Comp относится к общему исходному файлу библиотеки, включая директивы,
и одинаков для всех сборок. В коде нет комментариев.
Это явно выбранная общая мера сложности, а не число строк после препроцессора.

Числа из отчёта не подставляются в результаты: они зависят от процессора,
компилятора и реализации. В отчёте Comp указан как 35 и как 50, а для
многопоточной версии приведены разные значения Perf. Здесь все показатели
вычисляются из реально измеренного времени. Если базовая версия на Linux
выполняется меньше минуты, увеличьте `--iterations`, чтобы выполнить требование
задания о времени базовой обработки от 1 до 300 минут.

## Проверки

`tests/test_blur.cpp` является отдельной тестовой программой на C++.
Она сравнивает библиотеку с независимой прямой свёрткой 3×3, проверяет
ширины от 1 до 35, разные высоты, 0/1/4 итерации, 1/3 потока,
совпадение входного и выходного буфера и некорректные аргументы.
Python-тесты проверяют `ctypes`, неконтинуальный массив, постоянные цвета,
обработку ошибок, загрузку и сохранение PNG через CLI.

Локально выполнены сборка семи вариантов и все тесты на macOS arm64
с Homebrew GCC 16.2.0. Для повторения на macOS:

```bash
make clean
make -j4 test CXX=/opt/homebrew/bin/g++-16
```

Дополнительно выровненная SIMD-версия прошла C++-тест с AddressSanitizer
и UndefinedBehaviorSanitizer (Apple Clang). В ассемблере GCC при `-O0`
проверено наличие векторных инструкций `fadd/fmul .4s`.

Реальный локальный замер: 1920×1080 RGB, 1000 итераций, один замер,
4 потока у OpenMP, Comp=113. Все результаты совпали с базовой версией.

| Вариант | T, с | Perf, с⁻¹ | P |
| --- | ---: | ---: | ---: |
| scalar_o0 | 16.626061 | 0.060147 | 532 |
| scalar_o3 | 4.061989 | 0.246185 | 2178 |
| simd_o0 | 11.030566 | 0.090657 | 802 |
| simd_o3 | 1.477817 | 0.676674 | 5988 |
| aligned_o0 | 9.953776 | 0.100464 | 889 |
| aligned_o3 | 1.637571 | 0.610661 | 5404 |
| parallel | 0.690972 | 1.447238 | 12807 |

Это замеры macOS, а не Fedora из отчёта. На этой машине выравнивание
не ускорило оптимизированную однопоточную версию. Базовый замер короче
требуемой минуты; для сдачи следует повторить измерения на Linux,
подобрав число итераций под производительность машины.

Расширение `.so` сохранено для единых путей, однако локальная macOS-сборка
имеет формат Mach-O. Для Linux нужно заново выполнить `make clean && make`.
Linux-проверка в текущей среде не выполнена: Docker daemon недоступен,
а запуск Parallels заблокирован ограничениями среды.

## C ABI

```c
int gaussian_blur(const float *input, float *output, int width, int height,
                  int iterations, int threads);
```

Массивы содержат `width * height * 3` элементов в порядке RGB, построчно.
Вызывающий код отвечает за размер буферов. Ноль итераций копирует вход.
Коды возврата: 0 — успех, 1 — неверные аргументы, 2 — ошибка выделения памяти.
Библиотека не выполняет файловый ввод-вывод.
